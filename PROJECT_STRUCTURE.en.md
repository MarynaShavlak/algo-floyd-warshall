**Separation of responsibilities.**

- **`core.py`** does not depend on any graphics libraries — it is pure algorithm that can be imported anywhere. It contains `floyd_warshall_steps` (the instrumented version with snapshots), `floyd_warshall` (compact), `reconstruct_path`, `has_negative_cycle`, and the helper `adjacency_to_inf` (converts the `0 == no edge` convention to the `∞` convention).
- **`style.py`** is the single source of the visual theme: the color palette as named constants, `FIGURE_DPI`, fonts, and `configure_style()`. The look of every figure can be changed from one place.
- **`i18n.py`** provides bilingual labels: `t()` returns a string in the current language (`uk` by default / `en`), and `set_lang()` switches it. The dictionary key is the Ukrainian string itself, so the Ukrainian figures stay byte-for-byte unchanged. Every visible label in `visualization.py` and the examples is wrapped in `t()`.
- **`visualization.py`** (requires `matplotlib` and `networkx`) takes the palette from `style.py` and draws graphs, matrices, and step frames. The public `format_value` formats a matrix value (`∞` for missing ones).
- **`animation.py`** stitches frames into a looping **GIF** (via Pillow, always) and additionally encodes the same sequence into an **MP4** (via `ffmpeg`, if available). GIF is the guaranteed format for inline viewing; MP4 is a lighter file with playback controls.
- **`walkthrough.py`** builds the step-by-step "code ↔ matrix" panels: a step journal (`build_overview_steps` / `build_cell_steps`) with a code-line highlight map, the code panel (`draw_code_panel`), and a grid composer (`draw_code_walkthrough_grid`); the right panel reuses `draw_matrix`. The color of a code line encodes which branch fired (active / update / no change).
- **`examples/_common.py`** removes duplication between the examples: the `Agg`/path setup, `save_figure`, `save_anim` (GIF+MP4), language selection, printing paths, and the `GraphExample` dataclass that ties together vertex labels, the adjacency matrix, and coordinates.
- **`examples/_graphs.py`** is the single source of truth for the three teaching graphs (`ABCDEF`, `PQRS`, `XYZ`); all examples import them, so the adjacency matrices and coordinates are defined exactly once.
- The scripts in **`examples/`** simply take the graph they need from `_graphs.py`, call the algorithm and the drawing functions, and save the figures.
