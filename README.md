# Алгоритм Флойда–Воршала: покроковий розбір

[![GitHub repo](https://img.shields.io/badge/GitHub-algo--floyd--warshall-181717?logo=github)](https://github.com/MarynaShavlak/algo-floyd-warshall)

**🇺🇦 Українська**  ·  [🇬🇧 English](README.en.md)

**Алгоритм Флойда–Воршала** знаходить **найкоротші шляхи між усіма парами вершин** (all-pairs shortest paths) у зваженому графі. Працює і з додатними, і з від'ємними вагами ребер, але **не допускає циклів від'ємної ваги**.

Це класичний приклад **динамічного програмування**: відстані між парами вершин поступово вдосконалюються, додаючи по одній «дозволеній проміжній вершині» за раз.

Репозиторій — навчальний матеріал: чиста реалізація алгоритму + докладні візуалізації кожного кроку. Увесь розбір нижче відтворюється кодом із [`examples/`](examples), а рисунки лежать у [`docs/images/`](docs/images).

> **Про назви вершин.** Вершини у графі зазвичай нумерують `0–5`. Щоб їхні назви не плутались зі змінною циклу `k`, тут вершини названо **літерами `A–F`** (`A=0, B=1, C=2, D=3, E=4, F=5`).

<a id="intuition"></a>

## Інтуїція: що таке `k` і навіщо кроки

Найважливіше для розуміння: **`k` — це вершина графа, а не окремий лічильник кроків.** Зовнішній цикл проходить вершини по черзі, і `k` на кожному кроці — це **та вершина, яку ми щойно «дозволили» використовувати як проміжну (пересадкову) точку**. Тобто `k = A` означає не «нульовий крок», а «тепер маршрутам дозволено йти транзитом через вершину A».

### Аналогія — пересадкові аеропорти

Уявіть вершини як **аеропорти**, а ребра — як **прямі рейси** з їхньою тривалістю. Спочатку матриця `D` знає лише *прямі* перельоти. Ми хочемо знайти найкоротший час між кожною парою аеропортів, дозволяючи пересадки.

![Карта аеропортів: вершини = аеропорти, ребра = прямі рейси](docs/images/airport_map_abcdef.png)

Алгоритм «відкриває» аеропорти як дозволені пересадкові вузли **по одному**:

- `k = A`: «віднині можна робити пересадку в A». Для кожної пари `(i, j)` питаємо: чи `(найкращий i→A) + (найкращий A→j)` швидше за поточний `i→j`? Якщо так — оновлюємо.
- `k = B`: «тепер можна пересідати **також** у B» (вже маючи A). Перевіряємо всі пари знову.
- … і так для **кожної** вершини.

Сам крок перевірки для однієї пари — це і є *релаксація*: порівнюємо **прямий рейс** із **пересадкою через `k`** і лишаємо коротший варіант. У цьому і вся формула `min(пряме, через k)`:

![Прямий рейс проти пересадки через хаб k](docs/images/airport_relaxation.png)

Відкриваючи хаби по черзі, маршрути поступово коротшають: спершу для пари може не бути **жодного** шляху, потім з'являється бодай якийсь, а з кожним новим дозволеним хабом — дедалі коротший:

![Хаби-аеропорти відкриваються по черзі, і маршрут коротшає](docs/images/airport_progressive.png)

▶️ Те саме в русі — відкриваємо хаби по черзі, і маршрут `i → j` коротшає `∞ → 12 → 6`:

![Анімація: відкриття хабів по черзі вкорочує маршрут i → j](docs/images/airport_progressive.gif)

Коли відкрито всі вершини як пересадкові, ми перебрали всі можливі маршрути — і в `D` лишаються справжні найкоротші відстані.

### Чому це працює саме покроково

Коли черга доходить до `k`, значення `D[i][k]` та `D[k][j]` вже враховують пересадки через раніше відкриті вершини. Тому сума `D[i][k] + D[k][j]` — це найкращий маршрут `i → … → k → … → j`, що користується будь-якими вже дозволеними вузлами **плюс** самим `k`.

**Відповідь на типове запитання «що таке `k = A`?»**: це **вершина** (пересадковий вузол поточного кроку). Формально `k` — змінна циклу, але за змістом вона містить *назву вершини*. Порядок, у якому ми відкриваємо вершини, — `A, B, C, …`; тому «номер кроку» і «вершина» тут ідуть пліч-о-пліч.

<a id="idea"></a>

## Основна ідея (формальніше)

Позначимо $D^{(k)}[i][j]$ — довжину найкоротшого шляху з вершини $i$ у вершину $j$, **якщо як проміжні дозволено лише вже «відкриті» вершини** (множину $\{A, \dots, k\}$).

- $D^{(\text{поч})}$ — це просто прямі ребра (жодних проміжних вершин): нулі на діагоналі, ваги ребер, де вони є, і $\infty$ в інших місцях.
- На кожному кроці ми «вмикаємо» ще одну проміжну вершину $k$ і питаємо: *чи можна для пари $(i, j)$ скоротити шлях, пройшовши через $k$?*
- Після того, як перебрано всі вершини, у матриці залишаються справжні найкоротші відстані між усіма парами.

**Ключове спостереження.** Найкоротший шлях, що використовує вже відкриті проміжні вершини, або **взагалі не проходить** через $k$ (тоді відповідь та сама, що й до відкриття $k$), або **проходить** через $k$ рівно один раз — тоді він розпадається на дві частини: $i \to k$ та $k \to j$, кожна з яких користується лише раніше відкритими вершинами.

<a id="formula"></a>

## Формула оновлення (рекурентне співвідношення)

Звідси головна формула:

$$D^{(k)}[i][j] = \min\Big(D^{(\text{до } k)}[i][j],\; D^{(\text{до } k)}[i][k] + D^{(\text{до } k)}[k][j]\Big)$$

Тобто: *стара відстань* проти *шляху через нову проміжну вершину $k$*. Беремо менше.

**Чому матрицю можна оновлювати «на місці»** (без копії)? Під час кроку для $k$ значення $D[i][k]$ та $D[k][j]$ не змінюються, бо будь-яке їх оновлення мало б вигляд $D[i][k] = \min(D[i][k],\, D[i][k] + D[k][k])$, а $D[k][k] = 0$. Отже, рядок $k$ і стовпець $k$ під час «свого» кроку незмінні — результат той самий.

*(У коді ми все ж робимо копію перед кожним кроком — лише щоб підсвітити, які клітинки змінилися.)*

**Це і є весь алгоритм** — формула вище буквально стає потрійним циклом. Ось його серце з [`floyd_warshall_steps`](floyd_warshall/core.py) (повний код — із відновленням шляху через `nxt` та знімками для покрокових картинок — у [`floyd_warshall/core.py`](floyd_warshall/core.py)):

```python
for k in range(n):                      # «відкриваємо» проміжні вершини по черзі
    for i in range(n):                  # для кожної пари (i, j)…
        for j in range(n):
            via_k = dist[i][k] + dist[k][j]
            if via_k < dist[i][j]:      # чи коротший шлях i → j через k?
                dist[i][j] = via_k      # так — оновлюємо найкоротшу відстань
                nxt[i][j] = nxt[i][k]   # і запам'ятовуємо, що шлях іде через k
```

Зовнішній цикл по `k` — це і є послідовне «відкриття» вершин; два внутрішні перебирають усі пари `(i, j)`. Звідси $O(n^3)$ часу та $O(n^2)$ пам'яті.

### Граф із прикладу

Працюємо з **орієнтованим зваженим** графом (вершини перейменовано на `A–F`). Він заданий **матрицею суміжності**, де `0` означає відсутність ребра:

| i→j | A | B | C | D | E | F |
|---|---|---|---|---|---|---|
| **A** | 0 | 3 | 0 | 0 | 0 | 0 |
| **B** | 0 | 0 | 1 | 0 | 0 | 0 |
| **C** | 0 | 0 | 0 | 7 | 0 | 2 |
| **D** | 0 | 0 | 0 | 0 | 0 | 0 |
| **E** | 0 | 0 | 0 | 2 | 0 | 3 |
| **F** | 0 | 0 | 0 | 0 | 0 | 0 |

Ребра: `A→B (3)`, `B→C (1)`, `C→D (7)`, `C→F (2)`, `E→D (2)`, `E→F (3)`.

![Орієнтований зважений граф A–F](docs/images/graph_abcdef.png)

<a id="init"></a>

### Крок 1. Ініціалізація матриці відстаней

Будуємо стартову матрицю:
- `D[i][i] = 0` (відстань від вершини до самої себе);
- `D[i][j] =` вага ребра $i \to j$, якщо воно є;
- `D[i][j] = ∞`, якщо прямого ребра немає.

![Початкова матриця відстаней D](docs/images/matrix_initial_abcdef.png)

<a id="iterations"></a>

### Кроки 2–3. Ітерації та оновлення

Серце алгоритму — три вкладені цикли. Зовнішній цикл по `k` — це і є «відкриваємо чергову проміжну вершину»; два внутрішні перебирають усі пари `(i, j)`:

```python
for k in range(n):            # k = поточна проміжна вершина (A, B, C, ...)
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
```

У навчальній версії ([`floyd_warshall_steps`](floyd_warshall/core.py)) після кожного `k` ми зберігаємо **знімок** матриці та **множину змінених клітинок** (щоб їх підсвітити). Додатково ведемо матрицю `nxt` для відновлення самих шляхів: `nxt[i][j]` — наступна вершина на найкоротшому шляху з `i` до `j`.

▶️ А ось як саме **два внутрішні цикли** перебирають усі пари `(i, j)` за фіксованого `k` — на прикладі найпродуктивнішого кроку `k = C`. Помаранчева рамка — поточна клітинка, синій хрест — опорні рядок і стовпець `k`, зелене — щойно покращена відстань (докладний розбір цих чисел — нижче):

![Анімація: два внутрішні цикли перебирають усі пари (i, j) для k = C](docs/images/sweep_abcdef_k_C.gif)

<a id="walkthrough"></a>

### Покроковий розбір: матриця після кожної проміжної вершини `k`

**Нагадування:** `k` — це **вершина**, яку ми дозволяємо як проміжну (пересадкову) на цьому кроці, а не номер кроку.

Як читати візуалізацію:
- 🟦 **синя рамка** — поточна проміжна вершина `k` (її рядок і стовпець дають «опорні» значення $D[i][k]$ та $D[k][j]$);
- 🟩 **зелена клітинка** — відстань, яку щойно покращено на цьому кроці (у дужках — попереднє значення);
- `∞` — шляху поки що немає.

**Підказка для цього графа.** Корисною проміжною вершиною може бути лише «внутрішня» — у яку щось *входить* і з якої щось *виходить*. Тут це лише **B** і **C**. Вершини **A** і **E** — *джерела* (немає вхідних ребер), а **D** і **F** — *стоки* (немає вихідних ребер), тож кроки `k = A, D, E, F` нічого не змінять. Уся «робота» відбувається на `k = B` і `k = C`.

**Детальний кадр.** Під кожним кроком матриця показана у розширеному вигляді: опорний рядок і стовпець `k` підписані стрілками (це джерела значень `D[i][k]` та `D[k][j]`), а **в кожній клітинці, що може оновитися**, записано повну формулу вертикально: спершу символьно `D[i][j] = min( D[i][j], D[i][k]+D[k][j] )`, потім підстановка чисел `= min( … )`, і нарешті результат `= …` жирним (зеленим, якщо клітинка покращилася).

#### Проміжна вершина `k = A`

За цей крок відповідає **одна ітерація зовнішнього циклу** `for k` (тут `k = 0`, вершина `A`), яка виконує оновлення всієї матриці:

```python
for k in range(n):                 # k = 0 → проміжна вершина A
    for i in range(n):             # звідки (рядок)
        for j in range(n):         # куди (стовпець)
            distance[i][j] = min(
                distance[i][j],                   # стара відстань i → j
                distance[i][k] + distance[k][j]   # шлях i → A → j
            )
```

`A` — джерело (немає вхідних ребер), тож не може бути пересадковою. Очікуємо: **без змін**.

**Що означає `D[B][A] + D[A][C]`?** Це **вартість шляху з B до C, який проходить через A** (тобто `B → … → A → … → C`):
- `D[B][A]` — найкоротша відома відстань **з B до A**;
- `D[A][C]` — найкоротша відома відстань **з A до C**;
- сума — «дійти з B до A, а потім з A до C».

**Загальна ідея кроку.** Коли ми «відкриваємо» вершину `k` (тут A), для кожної пари `(i, j)` питаємо: *чи не вийде коротше, якщо дозволити маршруту зробити пересадку в `k`?* Найкоротший шлях `i → j` або **не проходить через `k`** (відповідь лишається старою, `D[i][j]`), або **проходить** (розпадається на `D[i][k] + D[k][j]`). Беремо менше.

**Чому тут виходить ∞.** У цьому графі у вершину A не входить жодне ребро, тож із B до A дістатися неможливо: `D[B][A] = ∞`. Тому `D[B][A] + D[A][C] = ∞ + ∞ = ∞` — маршрут через A не існує, і `min` лишає стару відстань.

```text
============================================================
Крок: проміжна вершина k = A
============================================================
Жодна відстань не покращилася на цьому кроці.
  Причина: у вершину A не входить жодне ребро (D[i][A] = ∞).
```

![Матриця D після відкриття вершини A](docs/images/step_abcdef_k_A.png)

#### Проміжна вершина `k = B`

`B` — внутрішня вершина. Через неї відкривається маршрут `A → B → C`, тож з'явиться `D[A][C] = 4`.

**Чому покращується саме `[A][C]`.** До цього кроку прямого шляху A→C не було (`D[A][C] = ∞`). Але з A до B дістатися можна (`D[A][B] = 3`), і з B до C теж (`D[B][C] = 1`), тож маршрут `A → B → C` існує й коштує `3 + 1 = 4`. Оскільки `4 < ∞`, `min` обирає новий шлях — клітинка стає зеленою.

**А ось де та сама формула поки що не спрацьовує** — для `[A][D]` при `k = B`:
`D[A][D] = min( ∞, D[A][B] + D[B][D] ) = min( ∞, 3 + ∞ ) = ∞`.
З A до B дістатися можна, але з B до D — ще ні (`D[B][D] = ∞`, бо з B виходить лише ребро в C). Маршрут `A → B → D` з'явиться пізніше — після відкриття C.

```text
============================================================
Крок: проміжна вершина k = B
============================================================
Покращено відстаней: 1
  D[A][C]: ∞ → 4   (бо D[A][B] + D[B][C] = 3+1 = 4)
```

![Матриця D після відкриття вершини B](docs/images/step_abcdef_k_B.png)

#### Проміжна вершина `k = C`

`C` — головний «хаб» цього графа. Очікуємо одразу **4 покращення** (зокрема `D[A][D] = 11`).

У неї **веде два шляхи** — `A → C = 4` (це насправді `A → B → C`, що з'явилося на кроці `B`) і `B → C = 1`; а з неї **виходять два ребра** — `C → D = 7` та `C → F = 2`. Тому, відкривши C, ми отримуємо `2 × 2 = 4` нові маршрути: з `{A, B}` у `{D, F}`. Усі рахуються за тією самою формулою `min( старе, D[i][C] + D[C][j] )`.

**`[A][D] → 11`** — `D[A][C] + D[C][D] = 4 + 7 = 11` (шлях `A → C → D`, повністю `A → B → C → D`).
**`[B][D] → 8`** — `D[B][C] + D[C][D] = 1 + 7 = 8` (шлях `B → C → D`).
**`[A][F] → 6`** — `D[A][C] + D[C][F] = 4 + 2 = 6` (шлях `A → C → F`, тобто `A → B → C → F`).
**`[B][F] → 3`** — `D[B][C] + D[C][F] = 1 + 2 = 3` (шлях `B → C → F`).

**Ключова ідея.** Числа `4` (для `A → C`) і `1` (для `B → C`) вже містять усі раніше дозволені пересадки. Тому, коли C додає свої вихідні ребра (`+7` до D, `+2` до F), формула автоматично «доклеює» нову ділянку до вже знайденого найкоротшого початку — і так із коротких шматків збираються довші маршрути. Це і є суть динамічного програмування у Флойда–Воршала.

```text
============================================================
Крок: проміжна вершина k = C
============================================================
Покращено відстаней: 4
  D[A][D]: ∞ → 11   (бо D[A][C] + D[C][D] = 4+7 = 11)
  D[A][F]: ∞ → 6   (бо D[A][C] + D[C][F] = 4+2 = 6)
  D[B][D]: ∞ → 8   (бо D[B][C] + D[C][D] = 1+7 = 8)
  D[B][F]: ∞ → 3   (бо D[B][C] + D[C][F] = 1+2 = 3)
```

### Результат і відновлення шляху

Після всіх ітерацій матриця містить найкоротші відстані між усіма парами. Наприклад, `D[A][D] = 11`. Але `D` каже лише **скільки коштує** найкоротший шлях, а не **яким він іде**. Щоб відновити сам маршрут, ми паралельно ведемо ще одну матрицю — `nxt`.

#### Матриця `nxt`: «куди ступити першим кроком»

Ідея проста: `nxt[i][j]` — це **наступна вершина після `i`** на найкоротшому шляху з `i` до `j`. Якщо для кожної пари знати «перший крок», увесь маршрут розгортається сам: ступаємо в `nxt[i][j]`, опиняємось у новій вершині й повторюємо, доки не дійдемо до `j`.

**Ініціалізація.** Спочатку відомі лише прямі ребра, тож перший крок шляху `i → j` — це сама `j` (якщо ребро є), інакше шляху ще немає (`None`):

```python
# nxt[i][j] = j для кожної відомої (скінченної) відстані, інакше None
nxt = [
    [j if dist[i][j] != INF else None for j in range(n)]
    for i in range(n)
]
```

**Оновлення разом із відстанню.** Щоразу, коли релаксація знаходить коротший шлях `i → j` *через* `k`, перший крок маршруту `i → j` стає таким самим, як перший крок маршруту `i → k`:

```python
if dist[i][k] + dist[k][j] < dist[i][j]:
    dist[i][j] = dist[i][k] + dist[k][j]
    nxt[i][j] = nxt[i][k]   # шлях i → j тепер починається так само, як i → k
```

Чому саме `nxt[i][k]`, а не `k`? Бо найкоротший шлях `i → k` сам міг проходити через раніше відкриті вершини. Нас цікавить **самий перший** крок усього маршруту `i → … → k → … → j`, а він збігається з першим кроком його початкової ділянки `i → k`.

#### Розгортання шляху

Маючи готову `nxt`, повний маршрут будуємо простим циклом «йди за вказівниками, доки не прийдеш» (це і робить [`reconstruct_path`](floyd_warshall/core.py)):

```python
def reconstruct_path(nxt, u, v):
    if nxt[u][v] is None:
        return None          # шляху не існує
    path = [u]
    while u != v:
        u = nxt[u][v]        # ступаємо на перший крок до v...
        path.append(u)       # ...і так, доки не дійдемо
        if len(path) > len(nxt):   # від'ємний цикл на маршруті —
            raise ValueError("маршрут проходить через від'ємний цикл")  # інакше зациклимось
    return path
```

**Приклад для `A → D`.** Розгортаємо за `nxt`: `A → nxt[A][D] = B`, далі `B → nxt[B][D] = C`, далі `C → nxt[C][D] = D` — прийшли. Отриманий шлях `A → B → C → D` точно відповідає `D[A][D] = 11`.

```text
       A    B    C    D    E    F
   A |   0    3    4   11    ∞    6
   B |   ∞    0    1    8    ∞    3
   C |   ∞    ∞    0    7    ∞    2
   D |   ∞    ∞    ∞    0    ∞    ∞
   E |   ∞    ∞    ∞    2    0    3
   F |   ∞    ∞    ∞    ∞    ∞    0

Найкоротший шлях A → D:  A → B → C → D   (довжина = 11)
Найкоротший шлях A → F:  A → B → C → F   (довжина = 6)
Найкоротший шлях A → C:  A → B → C   (довжина = 4)
```

![Найкоротший шлях A → D на графі](docs/images/path_abcdef_A_to_D.png)

## Від'ємні цикли

Алгоритм коректно працює з від'ємними **ребрами**, але **не з від'ємними циклами**: якщо такий цикл є, «найкоротшого» шляху не існує (його довжину можна зменшувати нескінченно).

Зручний спосіб **виявити** від'ємний цикл — запустити алгоритм і перевірити діагональ: якщо для якоїсь вершини `D[i][i] < 0`, вона лежить на досяжному від'ємному циклі.

> **Чого цей критерій не дає.** `D[i][i] < 0` сигналізує, що від'ємний цикл *існує* і що вершина `i` його досягає, але **не вказує, які саме ребра** утворюють цикл. Щоб дістати сам цикл, потрібен окремий прохід (наприклад, відстеження попередників). Тут ми обмежуємось фактом наявності — цього достатньо, щоб зрозуміти: результат алгоритму для такого графа недійсний.

```python
from floyd_warshall import floyd_warshall_steps, has_negative_cycle

# граф із 3 вершин (A, B, C) і циклом A → B → C → A вагою 1 + (-1) + (-1) = -1 < 0
neg = [
    [0,  1,  0],
    [0,  0, -1],
    [-1, 0,  0],
]
dist, _, _ = floyd_warshall_steps(neg)
print(has_negative_cycle(dist))   # → True  (на діагоналі є від'ємні значення)
```

```text
Діагональ матриці (вершини A, B, C): [-1, -1, -2]
Виявлено від'ємний цикл: True
```

## Приклад 2 — повністю від'ємний цикл (усі ребра від'ємні)

Розглянемо три вершини `X, Y, Z`, де **всі** ребра циклу від'ємні: `X → Y = −1`, `Y → Z = −1`, `Z → X = −1`. Сума ваг циклу = `−3 < 0` — це **від'ємний цикл**.

> **Чому без покрокових кадрів.** На відміну від прикладів 1 і 3, тут ми навмисно не показуємо матрицю «після кожного `k`»: для від'ємного циклу значення `D[i][j]` не сходяться до осмисленої відповіді (справжня — `−∞`), тож покрокові знімки лише створювали б ілюзію коректного результату. Натомість дивимось на діагональ підсумкової матриці — цього досить, щоб діагностувати проблему.

**Чому алгоритм не може це обробити.** Флойд–Воршал припускає, що найкоротші відстані — скінченні числа, і повертає скінченну матрицю. Але для такого графа ці числа **неправильні** (справжня відповідь — `−∞`). Ознака проблеми — діагональ: якщо після алгоритму `D[i][i] < 0`, вершина `i` лежить на досяжному від'ємному циклі (вона «повертається в себе» з від'ємною вагою).

```text
Діагональ матриці D після Флойда–Воршала (вершини X, Y, Z): ['-3', '-3', '-6']
Є вершина з D[i][i] < 0  →  виявлено від'ємний цикл: True

Числа поза діагоналлю алгоритм теж повертає скінченними, але вони НЕ є
справжніми найкоротшими відстанями — насправді для цих пар відповідь −∞.
```

## Приклад 3 — від'ємні ребра (вузли `P, Q, R, S`)

Флойд–Воршал, на відміну від Дейкстри, **коректно працює з від'ємними вагами** (якщо немає від'ємного циклу). Граф: `P→Q = 4`, `Q→R = −2` (від'ємне ребро), `R→S = 3`, `P→S = 10`. У вершину `P` не входить жодне ребро, з вершини `S` не виходить жодне ребро. Нижче — ті самі покрокові таблиці, що й для графа `A–F`.

> **Чому новий граф, а не A–F із від'ємними ребрами.** У графі A–F до кожної вершини веде **рівно один маршрут** (він деревоподібний), тож від'ємне ребро там лише змінило б якесь число — і не виникло б жодної «гонки маршрутів». А весь сенс від'ємних ваг саме в тому, що **довший обхід може обігнати пряме ребро**: тут пряме `P → S = 10` програє шляху `P → Q → R → S = 5`. Для цього потрібна пара вершин, у якої є *і* пряме ребро, *і* альтернативний обхід — тому беремо новий маленький граф, спеціально побудований навколо цього контрасту.

![Граф P, Q, R, S із від'ємним ребром Q → R = −2](docs/images/graph_pqrs.png)

![Початкова матриця D (P, Q, R, S)](docs/images/matrix_initial_pqrs.png)

### Крок: проміжна вершина `k = P`

Перша ітерація. У вершину `P` не входить жодне ребро, тож вона не може бути проміжною — **жодних змін**.

```text
============================================================
Крок: проміжна вершина k = P
============================================================
Жодна відстань не покращилася на цьому кроці.
  Причина: у вершину P не входить жодне ребро (D[i][P] = ∞).
```

![Матриця D після відкриття вершини P](docs/images/step_pqrs_k_P.png)

### Крок: проміжна вершина `k = Q`

Через `Q` з'являється шлях `P → R`:
`D[P][R] = min( ∞, D[P][Q] + D[Q][R] ) = min( ∞, 4 + (−2) ) = 2`.
Тут **уперше працює від'ємне ребро** `Q→R = −2`: маршрут `P → Q → R` коштує `4 − 2 = 2`.

```text
============================================================
Крок: проміжна вершина k = Q
============================================================
Покращено відстаней: 1
  D[P][R]: ∞ → 2   (бо D[P][Q] + D[Q][R] = 4+(-2) = 2)
```

![Матриця D після відкриття вершини Q](docs/images/step_pqrs_k_Q.png)

### Крок: проміжна вершина `k = R`

Одразу **два покращення**:
- `D[Q][S] = min( ∞, −2 + 3 ) = 1` — шлях `Q → R → S`;
- `D[P][S] = min( 10, 2 + 3 ) = 5` — шлях `P → Q → R → S`.

Найважливіше: **пряме ребро `P → S = 10` програє довшому шляху завдовжки `5`**, бо той використовує від'ємне ребро. Саме тому для графів із від'ємними вагами **не можна застосовувати Дейкстру**, а Флойд–Воршал працює правильно.

```text
============================================================
Крок: проміжна вершина k = R
============================================================
Покращено відстаней: 2
  D[P][S]: 10 → 5   (бо D[P][R] + D[R][S] = 2+3 = 5)
  D[Q][S]: ∞ → 1   (бо D[Q][R] + D[R][S] = -2+3 = 1)
```

![Матриця D після відкриття вершини R](docs/images/step_pqrs_k_R.png)

Остання ітерація. З вершини `S` не виходить жодне ребро — **жодних змін**.

```text
============================================================
Крок: проміжна вершина k = S
============================================================
Жодна відстань не покращилася на цьому кроці.
  Причина: з вершини S не виходить жодне ребро (D[S][j] = ∞).
```

![Матриця D після відкриття вершини S](docs/images/step_pqrs_k_S.png)

Підсумкова матриця містить найкоротші відстані між усіма парами. Звернімо увагу на `P → S`: маршрут іде `P → Q → R → S` (довжина 5), хоча є й пряме ребро `P → S = 10`.

```text
   R |   ∞    ∞    0    3
   S |   ∞    ∞    ∞    0

Найкоротший шлях P → R:  P → Q → R   (довжина = 2)
Найкоротший шлях P → S:  P → Q → R → S   (довжина = 5)
Найкоротший шлях Q → S:  Q → R → S   (довжина = 1)
```

<a id="complexity"></a>

## Складність і порівняння

**Час:** $O(n^3)$ — три вкладені цикли по $n$ вершин. **Пам'ять:** $O(n^2)$ на матрицю відстаней (плюс ще $O(n^2)$, якщо відновлюємо шляхи).

| Задача / алгоритм | Складність | Від'ємні ваги | Коли краще |
|---|---|---|---|
| **Флойд–Воршал** (усі пари) | $O(n^3)$ | так (без від'ємних циклів) | щільні графи, потрібні всі пари, простий код |
| Дейкстра з кожної вершини | $O(n \cdot (E + n)\log n)$ | **ні** | розріджені графи, лише додатні ваги |
| Беллман–Форд з кожної вершини | $O(n^2 \cdot E)$ | так | розріджені графи з від'ємними вагами |

Для невеликих/середніх щільних графів простота й сталий патерн доступу до пам'яті роблять Флойда–Воршала дуже зручним.

<a id="applications"></a>

## Де це застосовується

Алгоритм потрібен не лише в навчальних задачах — той самий «потрійний цикл» лежить в основі кількох практичних застосувань:

- **Маршрутизація в мережах.** Обчислення найкоротших шляхів між усіма вузлами — наприклад, у протоколах стану каналів або при плануванні трафіку, коли граф невеликий і щільний.
- **Транзитивне замикання графа** (алгоритм Воршала). Якщо замінити `min`/`+` на логічні `or`/`and`, та сама схема за $O(n^3)$ відповідає на питання «чи досяжна вершина `j` з вершини `i`?» для всіх пар.
- **Аналіз досяжності та залежностей.** Будь-де, де треба знати зв'язність «кожен з кожним»: залежності задач, досяжність станів, відношення «передує» у графі.
- **Метрики на графах.** Через матрицю всіх найкоротших відстаней рахують, наприклад, ексцентриситет вершин, діаметр і радіус графа.

Спільна риса всіх цих задач — потрібні **всі пари** відстаней/зв'язків одразу, а граф достатньо малий, щоб $O(n^3)$ був прийнятним.

<a id="clean"></a>

## Бонус: чистіша реалізація

У класичній реалізації (з угодою «`0` = немає ребра») ребро з вагою `0` неможливо відрізнити від відсутнього (через умову `if graph[i][j] != 0`). Надійніше задавати матрицю одразу через $\infty$ для відсутніх ребер — тоді коректно підтримуються й ребра нульової ваги. Сам алгоритм стає зовсім коротким (див. [`floyd_warshall`](floyd_warshall/core.py)):

```python
def floyd_warshall(adj):
    '''adj[i][j] = вага ребра або float('inf'), якщо ребра немає; 0 на діагоналі.'''
    n = len(adj)
    dist = [row[:] for row in adj]
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist
```

Той самий граф `A–F`, але вже з `∞` замість `0` для відсутніх ребер, дає той самий результат:

```text
       A    B    C    D    E    F
   A |   0    3    4   11    ∞    6
   B |   ∞    0    1    8    ∞    3
   C |   ∞    ∞    0    7    ∞    2
   D |   ∞    ∞    ∞    0    ∞    ∞
   E |   ∞    ∞    ∞    2    0    3
   F |   ∞    ∞    ∞    ∞    ∞    0
```

<a id="summary"></a>

## Підсумок

- `k` — це **вершина** (пересадковий вузол поточного кроку), яку ми «відкриваємо» як дозволену проміжну; вершини відкриваються по черзі `A → F`.
- Формула: $D^{(k)}[i][j] = \min\big(D[i][j],\, D[i][k] + D[k][j]\big)$ — «старий шлях» проти «шляху через нову проміжну вершину».
- Ініціалізація: нулі на діагоналі, ваги ребер, решта — $\infty$.
- Корисні лише «внутрішні» проміжні вершини; у нашому графі вся робота сталася на `k = B` і `k = C`.
- Складність $O(n^3)$ часу та $O(n^2)$ пам'яті; від'ємні цикли заборонені (їх можна виявити за `D[i][i] < 0`).
- Маршрути відновлюються через матрицю наступних вершин `nxt`.
